# Bug Report

## Summary

**Title**: Overlapping Battle navigation inputs cause command focus to freeze
**ID**: BUG-0001
**Severity**: S3-Minor (provisional; escalate to S2-Major if input does not recover after all directions are released)
**Priority**: P2-Next Sprint
**Status**: Open
**Reported**: 2026-08-24
**Reporter**: Manual Battle HUD playtest

## Classification

- **Category**: UI / Input
- **System**: Battle command navigation
- **Frequency**: Reproducible with overlapping directional inputs; exact rate not measured
- **Regression**: Unknown

## Environment

- **Build**: `c98acee` plus local Battle HUD Blueprint work
- **Platform**: Windows, Unreal Editor PIE
- **Scene/Level**: `FoundationMap`
- **Game State**: Battle command menu active with command focus available

## Reproduction Steps

**Preconditions**: Start PIE in `FoundationMap`, wait for the Battle command menu, and begin with Fight focused.

1. Press and hold Up.
2. Without releasing Up, press and hold Down.
3. Release Up while continuing to hold Down.
4. Without releasing Down, press and hold Right.
5. Release Down while continuing to hold Right.
6. Continue changing overlapping directional inputs without first returning every direction to neutral.

**Expected Result**: Each newly valid direction updates command focus once, and command navigation remains responsive during and after overlapping input transitions.

**Actual Result**: Only the first directional input is handled. Later overlapping direction changes are ignored, and command focus stops responding.

## Technical Context

- **Likely affected files**:
  - `Game/Source/PokemonSolarus/Private/UI/BattlePlayerController.cpp`
  - `Game/Source/PokemonSolarus/Public/UI/BattlePlayerController.h`
  - `Game/Content/Input/IA_BattleNavigate.uasset`
  - `Game/Content/Input/IMC_Battle.uasset`
- **Related systems**: Enhanced Input, Axis2D command navigation, Battle HUD focus presentation
- **Possible root cause**: Unconfirmed. `IA_BattleNavigate` is bound only to `ETriggerEvent::Started`, and `HandleBattleNavigate` samples and quantizes one Axis2D value per invocation. Overlapping key changes may leave the action active without producing another Started invocation. Equal-magnitude X/Y input is also deliberately quantized to zero. The exact Enhanced Input transition sequence must be verified before choosing a fix.
- **Coverage gap**: Existing command-widget tests call `Navigate` with isolated cardinal values and do not reproduce overlapping physical-input lifecycles through `ABattlePlayerController`.

## Evidence

- **Logs**: No related error log captured.
- **Visual**: Manual actual-size PIE observation. Normal press-release navigation completed the Fight -> Bag -> Run -> Pokemon -> Fight cycle and all four Lifted Gem focus states passed. The freeze appeared only during overlapping directional input transitions.
